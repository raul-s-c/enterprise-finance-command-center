# v0.25 Status — CAPEX project-to-asset lifecycle

Version 0.25 adds a controlled project-level fixed-asset rollforward to the
CAPEX workspace. It links approved project events and posted spend journals to
construction in progress, non-cash commissioning into PPE, useful life,
modeled depreciation and net book value.

## Evidence contract

- Each SPEND event must match both its posted CIP debit and cash credit journal
  lines. GO_LIVE must match the PPE debit and non-cash CIP credit.
- Project CIP and gross PPE reconcile to legal-entity ledger balances; project
  and opening-pool depreciation reconcile to monthly 6100_DEPRECIATION and
  1590_ACCUM_DEP balances.
- Project depreciation is derived from approved budget and useful life because
  the existing ledger records depreciation in one aggregated monthly journal
  per entity. That journal ID is preserved and clearly labelled as aggregate,
  not as an asset-level posting.
- Depreciation on the opening PPE pool is not assigned an assumed useful life.
  It remains the residual of the entity's posted monthly depreciation after
  modeled project depreciation; the residual cannot be negative, and the
  depreciation expense and accumulated-depreciation postings must reconcile.
- Opening PPE remains an entity-level pool. No individual legacy asset IDs,
  disposals, impairments or asset-level depreciation postings are invented.
- A mobile-friendly, searchable project register shows the cash → CIP → PPE →
  depreciation path and underlying SPEND / GO_LIVE journal IDs.

## Published files

- `data/processed/fixed_asset_project_register.csv`
- `data/processed/fixed_asset_project_events.csv`
- `web/data/fixed_asset_detail.json` (lazy-loaded by the CAPEX cockpit)

## Controls

The release adds event-to-journal, gross-PPE, CIP, accumulated-depreciation and
monthly depreciation checks. Any gap above EUR 0.05 blocks publication. The
register does not change the journal, cash flow, PPE, depreciation expense or
forecast balances.
