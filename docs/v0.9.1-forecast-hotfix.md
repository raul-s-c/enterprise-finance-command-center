# v0.9.1 Forecast Scale Hotfix

Version 0.9.1 fixes a forecast-grain error detected after validating the first production Annual Budget / FY Outlook release.

## Issue

The forecast engine previously calculated its Entity / Division baseline by averaging operating transaction rows directly.

With dozens or hundreds of customer-product rows inside one month, this understated the monthly business run-rate by roughly the transaction count.

The error could pass ordinary reconciliation tests because the forecast dataset was internally consistent even though its economic scale was wrong.

## Correction

The forecast baseline is now built as:

```text
Operating transaction rows
-> monthly Entity / Division totals
-> complete six-month monthly grid
-> de-seasonalized monthly run-rate
-> structural growth
-> target-month seasonality
-> historical forecast-bias correction
-> Base / Upside / Downside scenarios
```

Gross-margin, marginal-contribution and OPEX assumptions are calculated from the same aggregated monthly history.

## New hard control

The next-month Base forecast is compared with the trailing six-month actual monthly revenue run-rate.

```text
Next-month Base Forecast
/
Trailing six-month actual monthly revenue
```

The release is blocked unless the ratio remains between 55% and 165%.

This intentionally broad range permits seasonality, growth and bias correction while catching unit/grain failures such as a forecast at 1/50th or 1/100th of the current business scale.

## Validation

The hotfix was validated on GitHub Actions with the complete test suite and the 36-month finance build before merge.

The change does not alter historical actuals, accounting, Working Capital, provisions, Budget construction or consolidation. It regenerates forecast vintages, forecast accuracy and all FY Outlook views that depend on those forecasts.
